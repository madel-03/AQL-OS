# Telegram — ربط جارفس

البوت: `aql_jarvis_assistant_bot`. مفتاح BotFather يظل في الخادم فقط؛ لا ترسله في المحادثة أو تضعه في متغير VITE أو Git.

## 1. قاعدة البيانات

افتح `backend/migrations/telegram.sql` وانسخ محتواه إلى Supabase → SQL Editor → Run. رسالة `Success. No rows returned` طبيعية. الجداول مغلقة أمام المتصفح؛ الخادم يستخدم service_role الموجود بالفعل. لا حاجة لتغيير إعداد Google Calendar أو مفتاح تشفيره.

## 2. إعداد Render

في خدمة AQL-OS → Environment أضف:

| Key | Value |
| --- | --- |
| TELEGRAM_BOT_TOKEN | المفتاح الذي أعطاك BotFather، دون علامات تنصيص |
| TELEGRAM_BOT_USERNAME | aql_jarvis_assistant_bot |
| TELEGRAM_WEBHOOK_SECRET | نص عشوائي يولد بالأمر أدناه |
| TELEGRAM_WEBHOOK_URL | https://aql-os.onrender.com/api/telegram/webhook |

يستخدم `APP_URL` الموجود ويجب أن يكون `https://aql-os-orcin.vercel.app` (أو النطاق الفعلي لواجهتك). لا تغيّر باقي المفاتيح. لتوليد سر الويبهوك ونسخه للحافظة شغّل هذا السطر وحده في PowerShell:

```powershell
node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('hex'))" | Set-Clipboard
```

الصقه في `TELEGRAM_WEBHOOK_SECRET`. ليس هو مفتاح BotFather. لا تشارك أيًّا منهما.

انشر تحديثات الخادم والواجهة بعد إضافة المتغيرات. عند بدء الخادم يتحقق من أن المفتاح يعود إلى اسم البوت المحدد، ويسجل webhook عبر HTTPS مع `secret_token`. يظهر سجل `Telegram webhook ready` عند نجاح التسجيل. لا يحتاج الأمر إلى لصق المفتاح في رابط بالمتصفح أو تشغيل Shell في Render.

## 3. الربط الشخصي

1. افتح الموقع وسجّل الدخول، ثم اضغط «الخدمات» في شريط الصفحة.
2. اختر «أنشئ رابط الربط» ثم «افتح البوت واضغط Start».
3. اضغط Start داخل محادثة Telegram الخاصة بالبوت.
4. ارجع إلى الموقع؛ تظهر هوية الحساب خلال نحو خمس ثوانٍ (أو اضغط «حدّث الحالة»).
5. تأكد من اسم حساب Telegram ثم اضغط «هذا حسابي — أكّد الربط».

الرابط خاص، صالح عشر دقائق ويُستعمل مرة واحدة. فتح الرابط وحده لا يمنح البوت بيانات الحساب. تأكيد الموقع مطلوب. لا يمكن ربط محادثة Telegram واحدة بحسابي عقل مختلفين. عند وجود تعارض افصل الربط من الحساب السابق أولًا.

## 4. جرّب

- `/today`: مواعيد Google Calendar لليوم، والمهام غير المنجزة المستحقة اليوم أو المتأخرة؛ منطقة الجهاز وقت الربط محفوظة بالحساب.
- `/tasks`: حتى ١٢ مهمة من قائمة المهام المتبقية التي يقرأها البوت (حد جلب ١٠٠؛ القائمة الكاملة في الموقع).
- `/help`: المساعدة.
- `/unlink`: فصل الحساب فورًا. يمكن أيضًا فصله من الموقع.

هذه النسخة للقراءة فقط: لا تعدّل المواعيد أو المهام، ولا تنشئ تقارير، ولا تفهم التسجيلات الصوتية بعد. تذكيرات Telegram متاحة اختياريًا بعد الترحيل والإعداد الإضافي في TELEGRAM-REMINDERS-SETUP.md؛ تنبيهات المتصفح تبقى مستقلة. البوت يرد على الأوامر حتى والموقع مغلق إذا كان خادم Render متاحًا. خادم نائم/متوقف قد يؤخر الرد أو يمنعه؛ لا تعد هذه النسخة بخدمة تذكيرات دائمة.

## البيانات والأعطال

المحادثات الخاصة فقط مقبولة؛ المجموعات والرسائل التي لا تطابق هوية المرسل تُتجاهل. كل استعلام للمهام أو التقويم يخص المستخدم المرتبط بالمحادثة. عناوين المهام والمواعيد المطلوبة تُرسل إلى Telegram عند طلبها، ولا تُرسل إلى نموذج AI. جدول الربط يحفظ معرف المحادثة والحساب واسم العرض والمنطقة الزمنية. الرموز المؤقتة تُخزن hashed، وتُحذف بعد التأكيد/الإلغاء؛ تنظيف دوري للتذاكر المنتهية ومعرفات التحديثات الأقدم من أسبوع.

الخادم يفحص سر الويبهوك قبل قبول الطلب ويخزن update_id لمنع تكرار إرسال الرد عند إعادة التسليم. إذا انقطع الاتصال بعد قبول تحديث ولم يتأكد إرسال الرد، لا يعيد نفس التحديث تلقائيًا؛ أرسل الأمر من جديد. مفتاح Google يظل مشفرًا بالطريقة الموجودة؛ البوت يقرأ التقويم ويجدد الإذن عند الحاجة فقط.

- «نحتاج إعداد الخادم»: متغير ناقص/غير صالح أو نسخة خادم قديمة.
- «تعذّر ربط Telegram»: شغّل SQL وتأكد من مفاتيح الخادم الصحيحة، ثم راجع السجلات دون نشر أسرار.
- البوت لا يرد على Start: تحقق من اكتمال نشر Render وظهور `Telegram webhook ready`، ومن تطابق username مع المفتاح.
- طلب الربط منتهٍ/مستخدم: أنشئ رابطًا جديدًا؛ لا تنسخ رابط مستخدم آخر.
- التقويم غير متاح: جرّب تحديث مواعيدك من الموقع أو إعادة ربط Google، ولا تُفسّر تعذّر القراءة باعتباره عدم وجود مواعيد.

اختبارات محلية: `npm.cmd run test:telegram` و`node scripts/verify-telegram-ui.js` من backend مع تشغيل واجهة على 127.0.0.1:5175. تستخدم حسابات وخدمات وهمية ولا ترسل إلى البوت الحقيقي.
