# AQL-OS

Life management application using React, Vite, Express, and Supabase.

## Structure

- `src/App.jsx`: screens, charts, and voice controls.
- `src/main.jsx`: React entry point.
- `src/index.css`: application styles.
- `src/lib/supabase.js`: browser Supabase client.
- `src/lib/lang.js`: language context and dictionary.
- `src/lib/i18n.jsx`: language provider.
- `../backend/server.js`: API, authentication, AI providers, and TTS.
- `../backend/agent-tools.js`: agent tool registry and execution.
- `../backend/test.js`: manual simulation script; currently needs a bearer token before use.

`dist/` is generated by the build. `node_modules/` contains installed dependencies.
Both are excluded from version control.

## Development

Run `npm install` separately in frontend and backend.
Keep configuration in each directory's `.env`; never commit secrets.

Frontend variables:
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`
- `VITE_API_URL` (default: http://localhost:5000)

Backend variables:
- `SUPABASE_URL`
- `SUPABASE_SERVICE_KEY` (server only)
- `CEREBRAS_API_KEY`, `GROQ_API_KEY`, `GEMINI_API_KEY`
- `PORT` (default: 5000)

Run `npm start` in backend and `npm run dev` in frontend.
The project requires its Supabase tables and authentication configuration;
database migrations are not included.

## Checks

Frontend: `npm run build` and `npm run lint`.
Backend: `node --check server.js` and `node --check agent-tools.js`.
Existing lint errors remain to be addressed separately.
On Windows, use `npm.cmd` if PowerShell blocks `npm.ps1`.

## Research tasks

Open the chat page and use **Research & downloadable report**. Enter a topic;
AQL plans search queries, searches the web, reads up to five different sites,
compares excerpts, checks citation IDs, and produces a UTF-8 Markdown download.
Completed reports can also be downloaded as a formatted PDF or editable Word
document. Both exports include clickable references, headings and tables, with
right-to-left formatting for Arabic. The Markdown option remains available.
It requires at least two readable sources and never treats failed page reads as
evidence. The report records source URLs, retrieval times, and limitations.

The authenticated API is `POST /api/research` with `{ topic, lang }`, followed
by `GET /api/research/:id` for progress and results. Each user can run one task
at a time. Refreshing or leaving the page does not stop a task while the backend
process remains running; the browser restores the most recent task for that user.

Tasks are saved in `backend/data/research/` when the backend starts from its own
directory. Set `AQL_DATA_DIR` to an absolute path on a persistent volume in
production. Ephemeral deployments can lose this data. This first implementation
requires a continuously running Node process: interrupted tasks must be restarted
after a server restart. It does not yet provide a distributed worker or scheduler.
Download reports before replacing local storage or redeploying without a volume.

Source pages are treated as untrusted evidence. Only public HTTPS HTML/text pages
are read; PDF parsing and pages requiring JavaScript or sign-in are not supported.
Automated citation checks validate reference IDs, not the factual truth of every
model-generated sentence. This is excerpt-based research, not an exhaustive review.

Run `npm run test:research` in `backend/` to check the pipeline, citation rejection,
source restrictions, authentication, persistence, and isolation between users.

### PDF and Word export deployment

The backend uses `docx` for Word and Puppeteer/Chromium for PDF. Run `npm ci` in
the backend on deployment and allow Puppeteer's browser installation. The runtime
must have the Chrome system libraries installed and be able to launch headless
Chrome. If Chrome is provisioned separately, set `PUPPETEER_EXECUTABLE_PATH` to its
executable. Run as a non-root user with browser sandbox support.

The bundled open-source Noto Sans Arabic font lives in `backend/assets/fonts/`
with its OFL license, so PDF generation does not fetch fonts from the internet.
Keep this directory in the deployment. Word uses Arial and native RTL formatting.

`GET /api/research/:id/export?format=pdf` or `format=docx` requires the same user
authentication as the research task. Export failures leave the original report
available; they do not rerun research. At most two exports run concurrently per
backend process.

Run `node scripts/verify-report-export.js` from the backend to create Arabic and
English QA examples under ignored `data/export-qa/`. This launches headless
Chromium. PDF layout was visually checked on both languages. DOCX structure,
hyperlinks and RTL flags were checked; native Word/LibreOffice visual validation
requires an Office renderer installed on the machine.
